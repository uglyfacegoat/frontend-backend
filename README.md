# Канцтовары

Простой учебный интернет-магазин для защиты практик 5–7 по дисциплине «Фронтенд и бэкенд разработка». В каталоге четыре товара: тетрадь, папка, ручка и карандаш. Используются HTML, CSS и JavaScript без сборщика и backend.

Товары и цены демонстрационные. Форма проверяет данные и показывает учебное подтверждение, без реальной отправки и хранения данных.

## Запуск

```sh
python3 -m http.server 8817 --bind 127.0.0.1
```

Открыть [локальный магазин](http://127.0.0.1:8817/).

[Репозиторий](https://github.com/uglyfacegoat/frontend-backend) · [GitHub Pages](https://uglyfacegoat.github.io/frontend-backend/)

Текущие изменения подготовлены локально. Pages пока показывает предыдущую версию; новый магазин не опубликован.

## Соответствие ТЗ и Git

Методички допускают интернет-магазин или каталог услуг, без обязательной тематики. Для практик 5–7 требуются три HTML-страницы, общая навигация, форма из предыдущего этапа, Flexbox/Grid и БЭМ. Эти части реализованы. Отдельные страницы карточки товара и оформления заказа относятся к постановке итоговой КР, а не к обязательным пунктам практик 5–7.

| 5 | `feature/multi-page-navigation` | Проверены локально | Ветка, коммит и PR ещё не оформлены |
| 6 | `feature/flex-grid-navigation` | Проверены локально | Ветка, коммит и PR ещё не оформлены |
| 7 | `refactor/bem-css-classes` | Проверены локально | Ветка, коммит и PR ещё не оформлены |

Для каждого этапа по ТЗ нужно создать ветку, выполнить соответствующее изменение, сделать осмысленный коммит, push, создать PR в main и выполнить merge. После объединения — проверить GitHub Pages и показать историю, diff и PR преподавателю. Полное оформление сдачи пока не завершено.

Методичка использует имя `kr1-html-css-shop`; здесь сохранена предоставленная репа `frontend-backend`.

В исходной локальной копии обнаружен незавершённый интерактивный rebase main. Он не завершался и не отменялся. Для оформления новых этапов безопаснее использовать отдельную чистую копию репозитория. Посторонняя папка `crm-recovery-2026-09-21/` не относится к сайту: не включать её в коммиты или архив, не использовать `git add .` в исходной копии.

## Примеры БЭМ

Блок — `product-card`; элемент — `product-card__title`; модификатор — `product-card product-card--writing`. Кнопки используют `button button--primary` и `button button--secondary`.

Основные блоки: `site-header`, `site-nav`, `breadcrumbs`, `hero`, `section`, `products-grid`, `product-card`, `catalog-layout`, `catalog-filters`, `catalog-products`, `filters-form`, `order-dialog`, `order-form`, `site-footer`.

`id` используется для якорей, JavaScript, label и ARIA-связей. CSS-оформление строится на классах; inline-стилей нет. Собственные ООП-классы в код сайта не добавлялись: пример `Product` в шпаргалке служит для объяснения понятий.

## Проверки

После смены темы проверены три страницы на 390, 768 и 1440 px: ссылки, якоря, метаданные, картинки, отсутствие горизонтального скролла и раскладка. Проверены выбор товара, открытие/закрытие dialog, фокус, Escape, неверные и корректные поля, повторная заявка без POST-запроса; фильтрация, неверный диапазон, пустой результат и сброс. Просмотрены скриншоты.

Синтаксис: `node --check js/main.js`. Оформление diff: `git diff --check`. Это локальная проверка Chrome; реальный телефон, другие браузеры и полная проверка доступности не заявляются.

Для повторения нужен запущенный сервер и доступный Node.js с Playwright. На этом компьютере используется готовый пакет без установки зависимостей:

```sh
NODE_PATH=/Users/aroslavzavgorodnev/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/node_modules \
CHROME_PATH='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' \
TEST_OUTPUT_DIR=/private/tmp/stationery-browser-qa \
node tests/browser.cjs
```

`TEST_BASE_URL` позволяет изменить адрес сервера. JSON и скриншоты записываются в `TEST_OUTPUT_DIR`.
