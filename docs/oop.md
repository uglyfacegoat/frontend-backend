# ООП — вопросы для защиты

Дополнительная подготовка по словам преподавателя: «ООП», «поле / атрибут», «принципы», «методы», «экземпляр». Это отдельные вопросы к защите, а не раздел методичек практик 5–7.

## Короткие ответы вслух

| Вопрос | Ответ |
| --- | --- |
| Что такое ООП? | Объектно-ориентированное программирование — подход, в котором программа строится из объектов, объединяющих данные и поведение. |
| Что такое класс? | Описание того, какие данные и методы будут у объектов данного типа. Например, `Product` описывает товар. |
| Что такое объект и экземпляр? | Объект — конкретная сущность в программе. Экземпляр класса — объект, созданный на основе этого класса. Тетрадь и ручка могут быть разными экземплярами `Product`. |
| Что такое поле или атрибут? | Данные объекта, например название или цена. В JavaScript обычно говорят «свойство»; точное различие терминов зависит от языка. |
| Что такое метод? | Функция, связанная с объектом или классом и описывающая его поведение. Например, метод изменения цены. |
| Какие основные принципы? | Инкапсуляция, наследование и полиморфизм. Абстракцию также часто выделяют как четвёртый принцип. |

## Принципы с примерами

**Инкапсуляция** объединяет данные и операции над ними, ограничивая доступ к внутреннему состоянию. Например, закрытую цену меняем через метод, который запрещает отрицательные значения. Это не просто объединение функций в одном файле.

**Наследование** позволяет производному классу использовать и расширять возможности базового. Например, `Notebook` наследует название и цену от `Product` и добавляет количество листов.

**Полиморфизм** позволяет работать с разными объектами через общий интерфейс, получая соответствующее каждому типу поведение. Например, у товара и тетради есть `getDescription()`, но тетрадь возвращает ещё и количество листов.

**Абстракция** выделяет нужные для задачи характеристики, скрывая лишние детали. В каталоге товару нужны название и цена; процесс производства тетради моделировать не нужно.

Если преподаватель просит три принципа — назови инкапсуляцию, наследование и полиморфизм. Если четыре — добавь абстракцию и объясни каждый на примере.

## Один пример на JavaScript

Это учебный пример для объяснения. В код сайта эти классы не добавлены.

```js
class Product {
  name;                    // публичное поле экземпляра
  #price;                  // приватное поле экземпляра

  constructor(name, price) {
    this.name = name;
    this.setPrice(price);
  }

  get price() {            // свойство с геттером
    return this.#price;
  }

  setPrice(price) {        // метод с проверкой
    if (!Number.isFinite(price) || price < 0) {
      throw new Error('Цена должна быть неотрицательным числом');
    }
    this.#price = price;
  }

  getDescription() {
    return `${this.name}: ${this.price} ₽`;
  }
}

class Notebook extends Product {
  sheets;

  constructor(name, price, sheets) {
    super(name, price);     // конструктор родительского класса
    this.sheets = sheets;
  }

  getDescription() {       // переопределение метода
    return `${super.getDescription()}, ${this.sheets} листов`;
  }
}

const pen = new Product('Ручка синяя', 40);
const notebook = new Notebook('Тетрадь', 80, 48);

for (const product of [pen, notebook]) {
  console.log(product.getDescription());
}
// Ручка синяя: 40 ₽
// Тетрадь: 80 ₽, 48 листов
```

Здесь `Product` и `Notebook` — классы; `pen` и `notebook` — переменные, содержащие ссылки на экземпляры. `name`, `#price`, `sheets` — поля; `setPrice` и `getDescription` — методы. `price` читается как свойство, хотя получение значения реализовано геттером. Внешний код не может напрямую обратиться к `#price`.

## Частые уточнения

**Чем поле отличается от метода?** Поле хранит данные: `pen.name`. Метод выполняет действие и вызывается со скобками: `pen.getDescription()`.

**Что такое конструктор?** Специальный метод инициализации экземпляра. Выражение `new Product(...)` создаёт экземпляр и запускает конструктор.

**Что такое `this`?** В обычном вызове `pen.setPrice(50)` это объект `pen`. В JavaScript значение `this` зависит от способа вызова; оно не всегда автоматически равно экземпляру.

**Что такое `extends` и `super`?** `extends` объявляет наследование; `super(...)` вызывает конструктор родителя, а `super.getDescription()` — его метод.

**Класс в HTML и класс в ООП — одно и то же?** Нет. `class="product-card"` задаёт имена для CSS и поиска элемента. `class Product` объявляет класс JavaScript.

**Атрибут HTML и свойство объекта — одно и то же?** Это разные вещи, хотя некоторые связаны. В `<input value="80">` атрибут задаёт исходное значение; `input.value` показывает текущее, которое может измениться после ввода.

**Есть ли ООП в нашем проекте?** Собственные классы товаров не создавались: логика написана функциями и обработчиками событий. При этом мы работаем с DOM-объектами: у `dialog` свойство `open` показывает состояние, а методы `showModal()` и `close()` открывают и закрывают окно.

**Инкапсуляция и абстракция отличаются?** Инкапсуляция отвечает за границы доступа и управление состоянием, абстракция — за выделение существенных для задачи возможностей.

**Наследование обязательно?** Нет. Можно объединять объекты через композицию: например, корзина содержит товары, а не наследует от товара. Наследование подходит для связи «является разновидностью».

**Классы JavaScript устроены так же, как в Java?** Не полностью. В JavaScript классы используют прототипную модель наследования. На защите общие понятия можно объяснять одинаково, но детали языка отличаются.

## Что повторить перед защитой

Уметь назвать класс, экземпляр, поле и метод в примере; объяснить четыре принципа; отличить CSS-класс от класса ООП и HTML-атрибут от свойства JavaScript. Собственные ООП-классы в учебном примере не выдавать за реализацию магазина.
